# Android 1.2.2 — 2026-10-18

VersionCode 5. The website now offers clearly labelled arm64-v8a and armeabi-v7a installers, each containing the full app for its architecture. The legacy sonora-android.apk URL remains an alias of the arm64 build. Android 10 remains the minimum; use an up-to-date Android System WebView (Chrome 110+). No app features, dependencies or audio conversion settings changed.

The reported Samsung screenshot shows Android 14 and an A137F build, with a downloaded APK rejected as incompatible. The previous main installer was verified to contain only arm64-v8a native libraries. An unsupported OS architecture is the leading explanation; neither the screenshot nor the model name proves the phone's supported ABIs. A retry on the physical phone is still required. If it fails, capture the package install error and `adb shell getprop ro.product.cpu.abilist` before making further changes. Do not uninstall an existing copy to troubleshoot, because that removes its private library.

The arm64 release is 72,617,983 bytes (about 73 MB); arm32 is 65,965,167 bytes (about 66 MB). A 169,252,989-byte universal APK was built and verified, but is retained locally rather than published: it bundles multiple processor versions and exceeds Vercel Hobby’s 100 MB file limit. Each smaller installer contains all six upstream native payloads for its architecture, byte-identical to the universal build. No bitrate, features or native functionality were removed to reduce size. The release signature verifies and matches the existing certificate, preserving the update path. Minimum/target SDK remain 29/36. Gradle ABI filters explicitly exclude dependency architectures outside the supported set.

Packaging regression tests run the actual packager in an isolated source fixture. They verify that the website packages the smaller complete ARM builds, both choices are prominent, checksums match, and missing 32-bit build metadata rejects packaging even if a stale APK remains on disk. All 29 Node tests and 11 Android JVM tests passed; signed release, debug and instrumentation APK compilation passed.

The universal debug APK updated the existing Android 16 x86_64 emulator installation in place. A second install initially hit the emulator's storage reserve; Android cache reclamation allowed the final APK update without removing app data. All 12 native playback/engine instrumentation tests passed, and the app launched successfully. The suite covers local queue playback, automatic advancement, controller restrictions, queue recovery, caching, cancellation and validation. ARM payload contents and signing were checked statically; a physical ARM phone and Android 10–15 runtime coverage remain unverified.

The packaging command prepares the installer, smaller downloads, source and checksums for website deployment. The user authorized publishing the complete website with these smaller installers; deployment evidence is recorded in docs/vercel-launch.md. Existing YouTube connection/bot-check limitations described in the 1.2 release remain unresolved.

References: [Android ABI guide](https://developer.android.com/ndk/guides/abis) and [Android multiple-APK build documentation](https://developer.android.com/build/configure-apk-splits).
